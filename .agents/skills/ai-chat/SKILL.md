name: ai-chat
description: AI/chat architecture reference — providers, model allowlists, fallback rotation, step/token limits, message compaction, VFS caching, and stream error handling. Use when working on src/app/api/chat/route.ts, src/lib/provider.ts, src/lib/models.ts, src/lib/message-compaction.ts, the chat UI, or anything model/provider related.
---

- **No API key needed**: `MockLanguageModel` in `src/lib/provider.ts` returns canned components (counter/form/card).
- **Providers**: Google AI Studio Gemini free tier is primary (`GOOGLE_GENERATIVE_AI_API_KEY`; models in `GEMINI_FREE_MODELS` in `src/lib/models.ts`, in order: `gemini-3.6-flash` (default), `gemini-3.5-flash`, `gemini-3.5-flash-lite`; env override `GEMINI_MODEL`); Groq free tier is secondary (`GROQ_API_KEY`, optional `GROQ_BASE_URL`, models in `GROQ_FREE_MODELS`: `openai/gpt-oss-120b` (Groq default), `openai/gpt-oss-20b` — tool-calling models only). Groq is served via `@ai-sdk/openai-compatible` (`buildGroqModel`, provider name "groq", model.provider === "groq.chat") with `createReasoningNormalizingFetch` (renames Groq's `reasoning` → `reasoning_content`) and its own env-overridable token cap `groqMaxTokens()` (`MAX_TOKENS_GROQ`, default `MAX_TOKENS_GROQ_DEFAULT` = 8192). Gemini 2.5 models were removed — their free-tier quotas are effectively unusable — but the thinking-family helpers remain. With no Gemini key, Groq is the primary (default `DEFAULT_GROQ_MODEL`); a Groq selection without a Groq key degrades gracefully to the Gemini/default/mock path.
- **Fallback rotation**: Rate-limited/5xx/retired-model turns rotate through the remaining free models (`buildLanguageModel` in `src/lib/provider.ts`): the primary's own provider's models first (fallback priority order), then other configured providers, then the mock via `createRateLimitFallbackModel`. Gemini 2.5-family primaries stay within their thinking family; Gemini 3.x primaries (no request-level thinking config) may rotate cross-provider into Groq. Chain members may declare a per-member `maxTokens` (`FallbackChainMember`) since Groq caps completion far below the Gemini request-level cap — the wrapper substitutes it per call.
- **Chat API route**: `src/app/api/chat/route.ts` — uses `ai` SDK `streamText` with tools; rate-limited to 30 requests/min/IP (`RATE_LIMIT_*` in `src/lib/constants.ts`); `maxDuration = 120` for Vercel serverless.
- **Step/token limits** (`src/lib/constants.ts`): mock provider uses `maxSteps=4` (`MAX_STEPS_MOCK`); real providers use `maxSteps=10` (`MAX_STEPS_REAL`); test-connection requests use `maxSteps=1`, `maxTokens=64` (`MAX_TOKENS_TEST`).
- **Provider tuning**: `providerOptions.google = { thinkingConfig: { thinkingBudget } }` is sent **only for Gemini 2.5-family models** (`supportsThinkingBudget`, default 0 = thinking disabled, override via `GEMINI_THINKING_BUDGET`). Gemini 3.x models use `thinkingLevel` — unsupported by the pinned `@ai-sdk/google` (its zod schema strips it) — and can't disable thinking, so no thinking config is sent for them; they run on their defaults (medium for Flash, minimal for Flash-Lite). The pinned `@ai-sdk/google` is 1.2.x (ai SDK v4); the fallback chain must never mix 2.5/3.x families because providerOptions are request-level.
- **Gemini 3.x compat bridge** (`src/lib/gemini-3-compat.ts`, wired via `fetch` in `buildGoogleModel`): the pinned SDK predates Gemini 3, so the wrapper (a) injects `generationConfig.thinkingConfig = { thinkingLevel: "low", includeThoughts: true }` into 3.x requests — their default (medium) thinking otherwise burns the whole token cap before the first tool call, and "low" is the lowest level that still returns thought summaries ("minimal" thinks too little to produce any) so the chain of thought streams to the UI — and (b) captures `thoughtSignature` values from streamed responses and injects them into outgoing bare `functionCall` parts, because Gemini 3 400s ("Function call is missing a thought_signature") on follow-up steps otherwise. The signature map is global — concurrent requests can exchange signatures, which the API tolerates as degraded performance; only MISSING signatures hard-fail. Bridge until an ai v5 migration.
- **Token cap** (`src/lib/constants.ts`): everything non-test uses `MAX_TOKENS_GEMINI_3` (24k) now that all selectable models are Gemini 3.x — their thinking tokens count against the cap (~4-5k burned even at minimal; the mock ignores the cap). 3.x steps are slower (~20-60s) and the free tier 503s under load — the fallback rotation covers the 503s.
- **Payload reduction** (to cut provider token usage): full history kept for persistence as `originalMessages`; the model gets a compacted copy via `prepareModelMessages` (`src/lib/message-compaction.ts`) — history capped at 12 messages (`COMPACT_HISTORY_MAX_MESSAGES`), non-last assistant messages collapsed to ≤300-char text placeholders (`COMPACTED_MESSAGE_MAX_LEN`), `reasoning` parts stripped.
- **VFS caching**: server keeps an in-memory VFS cache (`vfsCache` in `route.ts`; `VFS_CACHE_TTL_MS` 10-min TTL, `VFS_CACHE_MAX_ENTRIES` 100) keyed by `project:${projectId}` or `anon:${sessionKey}`; clients omit `files` unless the revision is dirty and transparently retry on HTTP `428 VFS_RESYNC_REQUIRED` (`chat-context.tsx`).
- **Stream errors** are surfaced to the client via `getErrorMessage` (`describeError` in `route.ts`); the AI SDK's default masks them as "An error occurred." — `mapErrorMessage` in `ChatInterface.tsx` shows the real message unless it's exactly that mask.
- **AI tools**: `str_replace_editor` (view/create/replace/insert) and `file_manager` (rename/delete) — operate on VirtualFileSystem.
- **System prompt**: `src/lib/prompts/generation.tsx` — requires `/App.jsx` entrypoint, `@/` import alias, Tailwind CSS.
